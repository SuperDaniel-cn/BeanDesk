Run bean-check on the configured work folder, then apply trusted machine rules: the bundled locale pack plus last-approved custom TOML stored in BeanDesk. Live disk TOML is never the execution source. integrity is one of store-corrupt, unseeded, locale-mismatch, unapproved, ok (priority in that order). store-corrupt: approved copies could not be parsed; only the bundled pack ran. unseeded: this computer has no policy.json entry; call upgrade_ledger with an explicit locale after the user agrees to write, to seed; custom TOML is not applied until a person approves it in BeanDesk. locale-mismatch: .beandesk locale differs from BeanDesk; built-in rules still follow the BeanDesk locale. unapproved: disk custom files differ from the last approved copies and were not applied; ask the user to approve or revert in BeanDesk (MCP cannot approve, revert, or switch locale). ok: seeded, locale matches, custom hash matches. baselineDrift is true only when policies/base/rules.toml exists and differs from the pack; missing that file is not drift and does not fail the check. Errors fail the check; warnings are reported only. Unapproved or unseeded custom rules must fail; do not treat them as warnings.
