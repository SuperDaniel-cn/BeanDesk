# 日常记账

## 原则

- 财产独立：公司账只记对公经营收支，股东个人消费不入账。
- 垫资与出资分开：法人垫资记负债（如 `Liabilities:Owner-股东往来:Advance-法人垫资借款`），股东增资记权益（`Equity:Capital-实收资本:PaidIn-股东出资`）。还款摘要注明“还股东借款”或“还垫付款”。
- 三流一致：合同相对方、发票抬头与银行转账主体保持一致。
- 月末余额：Beancount 的 `balance` 在指定日期零点生效，核对月末公户余额时日期填次月首日。

## 入账前查重

助手在改 `config/accounts.bean`、`documents/` 或 `data/` 之前必须查重并汇总确认，未获用户确认不得写盘。这是助手操作纪律，不是 BeanDesk 或 `check_ledger` 的自动拦截。

- 有码用全号：增值税发票、数电票、合同等票面编号写入 `^inv-<完整号码>` 或 `^ct-<完整合同号>`，号码不得截成后几位。归档文件名应在日期之后加入 `.inv-<完整号码>` 或 `.ct-<完整合同号>`，见 `document-filing.md`。
- 无码不强造：转账截图、无号收据、银行回单，以及折旧、结息、期初、工资发放表等无外部凭证的分录，严禁编造 `^inv-` / `^rcpt-` 序号。银行流水号即使很长也不当作业务键。
- 必搜账套内已有的 `data/` 与 `documents/`。Fava 已通时可加做查询；服务未就绪不得中断入账。
- 编号匹配：有号码则搜完整 link 与文件名中的全号。可用号码后 8 位列出候选；后缀命中不得自动判重，也不得把短码写入分录。
- 业务指纹：无法定编号或编号匹配未命中时，只比前后 7 天内、金额完全相等、且同一往来单位或同一收入/费用科目的已入账分录。结转、折旧、结息、期初、工资发放表等无外部凭证的分录不做指纹查重。
- 单张或多张票据都汇总成一张确认清单：票据要素与编码、查重结果、拟新增科目、拟写入分录。查重命中时列出重叠分录的日期、摘要与金额，由用户选择：同一业务重复投递（该发票已入账且已归档则完全跳过；若之前只按银行回单入账、本次才补交发票原件，则不新增分录，仅归档发票文件，并在原分录补挂 `^inv-<完整号码>`）；分期收付款或往来挂账核销（关联同一 `^inv-…` 后继续入账）；恰好同金额的独立新业务（正常入账）。用当前对话列出选项并等待回复。

## 记账操作步骤

1. 查阅业务策略：调用 `list_policies` 与 `get_policy` 阅读 `policies/base/` 基线及企业自订制度 Markdown，了解科目与合规要求。
2. 提取票面信息并拟定科目：确认日期、往来单位、摘要、金额与收付款账户；只读 `config/accounts.bean` 判断科目是否已 `open`，此步不写盘。资金账户须标记 `cash: TRUE`；经营收支科目按 `chart-of-accounts.md` 标注现金流分类（`cashflow`）。
3. 按上一节完成查重，向用户展示汇总确认清单。未确认严禁写入 `config/accounts.bean`、`documents/` 与 `data/`。
4. 用户确认后再写盘：开立缺失科目；按 `document-filing.md` 将凭证存入 `documents/` 对应科目目录；在 `data/YYYY/YYYY-MM.bean` 写入分录。新建月份文件时，在 `data/YYYY/YYYY.bean` 中显式 `include` 该月文件。有完整票号的分录标注 `^inv-<完整号码>` 或 `^ct-<完整合同号>`。
5. 执行合规核查：调用 `check_ledger`，先执行 `bean-check` 校验语法与金额平衡；若 `policies/` 下配置了机器规则，再按生效区间核验。`ok` 只表示语法、平衡与已有机器规则匹配，不表示没有重复入账。保存后，BeanDesk 桌面界面在 Fava 重新加载时即可查阅更新后的报表；归档凭证若路径与日期匹配（或文件名包含交易 link 标记），可在日记账中穿透预览。

```beancount
2026-03-15 * "XX客户公司" "系统架构咨询服务款" #income ^inv-26312000000123456789
  Assets:Bank-银行存款:Main-基本户                    50000.00 CNY
  Income:Service-主营业务收入:Consulting-架构咨询服务 -50000.00 CNY
```
