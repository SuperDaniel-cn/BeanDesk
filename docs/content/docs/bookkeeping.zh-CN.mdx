BeanDesk 配合 Beancount 记录企业日常经营收支。所有的交易分录保存在本地明文账本文件中，原始发票与银行回单归档在凭证目录。系统直连本地账套与服务，不设中心化后端或云端账号，账本明文与凭证文件保存在用户本地工作目录中（若配置了 restic 远端对象存储，加密备份副本将传输至用户自备的目的地）。

本页详细说明账套的目录组织、中文科目在报表中的呈现原理、凭证归档机制以及日常记账操作流程。

## 账套目录结构

标准账套初始化后，工作目录具备以下完整结构：

```
<工作目录>/
├── .beandesk
├── .gitignore
├── main.bean
├── config/
│   ├── commodities.bean
│   └── accounts.bean
├── data/
│   └── YYYY/
│       ├── YYYY.bean
│       └── YYYY-MM.bean
├── documents/
└── policies/
    ├── README.md
    └── base/
        ├── chart-of-accounts.md
        ├── document-filing.md
        ├── bookkeeping-guide.md
        └── rules.toml      # zh-CN 预设写入（科目连字符命名规则）；en 预设不写机器规则
```

- .beandesk：版本化标记（含 `version` 与 `locale`），标识该工作目录为标准账套，并在桌面端“备份”页启用 Git 快照与 restic 加密备份。旧版纯文本 `beandesk` 视为第 1 版，可在设置页升级。
- main.bean：账本主入口文件，声明主币种并引入 commodities、accounts 与年度数据索引。文件中必须包含 option "documents" "documents"，以开启凭证目录的自动扫描与关联。
- config/commodities.bean：币种定义文件。中文预设默认写入人民币 CNY 与美元 USD。
- config/accounts.bean：已开立的会计科目字典。初始化时写入维持系统运转的最小基础账户（基本户与实收资本）；日常经营所需的业务科目由用户或 AI 助手参照 policies/base/chart-of-accounts.md 按需开立。
- data/YYYY/YYYY-MM.bean：按月份归档的具体交易分录文件。年度索引文件 data/YYYY/YYYY.bean 负责汇总引入每个月份。
- documents/：原始凭证归档目录，存放电子发票、银行回单与合同扫描件。
- policies/：记账合规策略目录。base/ 子目录包含随系统初始化的通用科目推荐字典、凭证单层归档规范、日常记账 SOP 与机器拦截规则（桌面端与默认 zh-CN 预设写入 rules.toml，en 英文预设不写）；企业亦可在根目录下添加自定的规章制度（如差旅报销制度）或自定 TOML 规则。
- .gitignore：版本控制忽略配置，默认忽略加密口令（.backup_key）、环境配置（.env）与备份仓库（backups/）。

## 报表里的科目名称呈现

Beancount 要求每一个科目路径节点必须以大写英文字母开头。为了让报表显示中文名称，BeanDesk 采用“英文前缀-中文名称”的连字符写法。

### 命名格式

```
根科目:大写英文分类-中文类别:大写英文子级-中文明细
```

示例：
- Assets:Bank-银行存款:Main-基本户
- Income:Service-主营业务收入:Consulting-架构咨询服务
- Expenses:Operations-管理费用:Rent-办公场地租金

### 界面提取规则

1. 平铺视图（日记账、凭证页、现金流量表与 BQL 查询）：系统会按冒号切分各级科目段落，提取每段最后一个连字符“-”后的中文部分，以“ · ”符号拼接展示。例如 Assets:Bank-银行存款:Main-基本户 呈现为“银行存款 · 基本户”；若段落中存在多个连字符（如 Main-XX银行对公户），仅取末尾连字符后的中文“XX银行对公户”。
2. 树形报表（资产负债表、利润表、试算平衡表）：按会计科目层级树展开，树中每一级节点（包含父级类别与明细科目）均提取其连字符后的中文名称呈现（如“银行存款”下缩进展开“基本户”）。
3. 英文与海外科目兼容：若科目未包含中文连字符（如 Assets:Bank:Checking），系统会完整保留并原样呈现原始 Beancount 路径。

注意：若需在报表中呈现中文名称，中文必须作为科目段落名称的一部分（通过连字符连接），Beancount 行末的注释分号（; 银行存款）仅作为文本备注，无法被报表提取。对于不带连字符的英文科目，界面会原样显示其英文名；仅在工作目录 policies/ 下启用了 zh-CN 机器命名规则（rules.toml）时，check_ledger 才会对未含连字符中文的科目报错拦截。

## 凭证归档与穿透预览

当收到银行电子回单、发票或合同扫描件时，将原始凭证存放在 documents/ 目录下。

### 归档路径映射规则

1. 科目层级转换为目录路径：将科目名称中的冒号“:”转换为目录分隔符“/”。
2. 连字符目录保持单层整体：包含连字符的段落（如 Bank-银行存款）作为单一文件夹，切勿拆分为 Bank/银行存款 两层子目录。
3. 文件命名规范：采用 YYYY-MM-DD.业务说明.扩展名 格式（使用点号分隔），日期必须与对应交易分录的日期完全一致。

### 归档路径示例

| 会计科目 | 对应凭证归档目录 | 凭证文件示例 |
| :--- | :--- | :--- |
| Assets:Bank-银行存款:Main-基本户 | documents/Assets/Bank-银行存款/Main-基本户/ | 2026-03-15.招商银行电子回单.pdf |
| Expenses:Operations-管理费用:Rent-办公场地租金 | documents/Expenses/Operations-管理费用/Rent-办公场地租金/ | 2026-03-01.物业租金发票.pdf |
| Income:Service-主营业务收入:Consulting-架构咨询服务 | documents/Income/Service-主营业务收入/Consulting-架构咨询服务/ | 2026-03-10.服务费增值税专票.pdf |

当凭证文件的日期与科目子目录路径均与分录匹配时（或文件名包含该笔交易的 link 标记），BeanDesk 会在日记账页面自动点亮凭证图标，点击即可在弹窗内直接穿透预览原始文件。

## 日常记账操作流程

记录一笔日常经营业务只需完成以下四步：

### 1. 确认科目已开立
在 config/accounts.bean 中确认所用科目已经执行了 open 指令。若需要开立新科目，货币资金账户需标注 cash: TRUE；经营收支科目需标注现金流量表分类（cashflow: "..."）：

```beancount
2020-01-01 open Assets:Bank-银行存款:Main-基本户 CNY
  cash: TRUE
2020-01-01 open Income:Service-主营业务收入:Consulting-架构咨询服务 CNY
  cashflow: "sales"
```

### 2. 存放凭证文件
将取得的发票或回单按上述规范存放至 documents/ 下对应的科目目录中。

### 3. 编写交易分录
在当月数据文件（例如 data/2026/2026-03.bean）中录入分录，并在 data/2026/2026.bean 中通过 include 引入该月：

```beancount
2026-03-15 * "XX科技有限公司" "企业架构咨询服务费" #consulting #invoice
  Income:Service-主营业务收入:Consulting-架构咨询服务      -20000.00 CNY
  Assets:Bank-银行存款:Main-基本户                         20000.00 CNY
```

### 4. 校验与核对
在命令行执行 bean-check main.bean，或通过本机 MCP 调用 check_ledger：
- 校验机制首先执行底层 bean-check 验证语法与分录借贷平衡；
- 若工作目录 policies/ 下配置了机器规则（如 zh-CN 预设的科目连字符命名规则，或自订 TOML 规则），将按生效区间一并执行合规核查（error 报错拦截，warning 仅提示）；未配置 TOML 时此步跳过。
保存账本文件后，BeanDesk 桌面界面在 Fava 重新加载时即可呈现更新后的报表；只要凭证归档路径与交易匹配（或文件名包含交易 link 标记），日记账中即可直接穿透预览。`check_ledger` 只校验账本文件，不检查凭证是否归档。

## 现金流量表映射与排障

BeanDesk 按直接法生成三类活动现金流量表，依据科目 open 指令上的元数据识别资金与业务流向：

1. 资金账户定义：在所有库存现金、银行存款或对公支付账户上标注 cash: TRUE。
2. 业务流向定义：
   - 单一流向科目：使用 `cashflow: "<代码>"`（如主营收入标 sales，日常采购标 purchases，税费标 taxes，员工工资标 wages，购建资产标 capex，股东出资标 capital）。
   - 双向往来科目：使用 `cashflow-in: "<代码>"` 与 `cashflow-out: "<代码>"`（如股东垫资借款：借款流入标 borrowings，归还垫资流出标 debt-principal）。

此元数据用于报表分类，不作为 `check_ledger` 的强校验项；若未配置相应元数据，相关收支将在报表中归入“未归类项目”，但账本仍能通过平衡校验。

### 常见排障提示

- 提示“未配置货币资金账户”：表示当前账套没有任何一个科目添加了 cash: TRUE 元数据。
- 金额归入“未归类项目”：表示发生资金收付的分录中，对方科目缺少 cashflow 行次代码。在 config/accounts.bean 中为该科目补充元数据即可自动归类。

全套 16 个标准现金流分类行次代码详见 [报表](/zh-CN/reports) 手册。
