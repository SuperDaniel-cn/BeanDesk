BeanDesk operates as a standard stdio MCP server. In Settings → General, click Copy Config to integrate command configurations into Cursor, Claude Desktop, or other local MCP hosts that can write the ledger work folder. A cloud chat that only accepts dropped images is not a posting path.

## Operating Principles

- Shared Configuration: Automatically resolves the ledger working directory and active Fava address configured in Settings, eliminating the need to hardcode paths in AI prompts.
- Read-Only Forwarding: Ledger tools forward read-only requests. If the underlying service is offline, tools return a descriptive status error rather than spawning processes in the background.
- Ledger Entries: Creating and editing transactions is handled by a local agent that can write monthly `.bean` files under the work folder; MCP does not expose entry write endpoints.
- Local vs cloud: Cloud-hosted models send invoices in the conversation off this machine. Invoices stay local only when both the model and the client that writes the work folder run on this computer.

## Tool Capabilities

- Ledger Services: Provides working directory identification, read-only financial statements, native BQL queries, document listing, and syntax checking. Supports initializing a new ledger skeleton upon explicit write confirmation, but exposes no transaction write endpoints or background process supervision. `check_ledger` runs bean-check (syntax and balance); it does not audit extra posting rules.
- Offline Handbook: AI assistants can invoke `get_handbook` to read any section of this documentation offline without requiring a running Fava engine.
- Work-folder policies: `list_policies` and `get_policy` list and read Markdown under `policies/` when that folder exists. They do not write entries.
- Security Boundaries: Protects sensitive local state; does not expose backup passphrases, raw document bytes, or private calendar subscription URLs.
