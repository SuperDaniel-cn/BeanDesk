BeanDesk works with Beancount to manage daily company operating income and expenditures. All transaction postings remain in local plain-text ledger files, while original invoices and bank statements are stored in the document repository. Financial statements are computed locally in real time without cloud dependencies.

## Operating Ledger Principles

When maintaining corporate management accounts, follow these foundational standards:

- **Entity Separation**: Corporate accounts record operating transactions only. Shareholder personal spending and household expenses must remain separate from company books.
- **Advances Distinct from Equity**: Shareholder or founder working capital advances should be booked as corporate liabilities (such as `Liabilities:Owner-股东往来:Advance-法人垫资借款`), keeping them strictly separate from paid-in capital (`Equity:Capital-实收资本:PaidIn-股东出资`). Note repayments as “Repay owner loan” or “Repay working capital advance”.
- **Three-Way Consistency**: For outgoing and incoming transactions, ensure contractual parties, invoice billing details, and corporate bank accounts remain aligned.
- **Complete Evidentiary Chain**: Retain invoices, electronic bank slips, or payment receipts for all revenues and expenses.
- **Month-End Reconciliation**: Beancount balance assertions (`balance`) take effect at midnight on the specified date. When validating month-end balances, use the first day of the subsequent month.

## Ledger Directory Anatomy

A standard BeanDesk ledger directory is organized as follows:

```
<work folder>/
├── .beandesk
├── .gitignore
├── main.bean
├── config/
│   ├── commodities.bean
│   └── accounts.bean
├── data/
│   └── YYYY/
│       ├── YYYY.bean
│       └── YYYY-MM.bean
├── documents/
└── policies/
    └── README.md
```

- `.beandesk`: Marks the working directory as a BeanDesk-initialized standard ledger. This marker unlocks the desktop Backup tab for configuring Git snapshots and restic encrypted backups (without this marker, backup operations remain disabled).
- `main.bean`: Primary ledger entry point. It declares the operating currency and includes `config/commodities.bean`, `config/accounts.bean`, and the year file. Must include `option "documents" "documents"` to activate automatic document scanning and linking.
- `config/commodities.bean`: Commodity declarations. Initialization writes CNY and USD.
- `config/accounts.bean`: Chart of accounts. Initialization writes the small-business template that follows the Beancount Chinese hyphen convention (`EnglishPrefix-中文名称`). Comments cannot stand in for the Chinese part of the account name. Any account referenced in postings must first be declared here via an `open` directive.
- `data/YYYY/YYYY-MM.bean`: Monthly transaction files. The annual file `data/YYYY/YYYY.bean` aggregates and includes each month.
- `documents/`: Central document archive storing electronic invoices, bank slips, and contracts.
- `policies/`: Optional bookkeeping and compliance policies directory. Basic bookkeeping works without this folder. It may contain guidance documents (Markdown files for AI assistants to follow specific account and document requirements) and automated rules (TOML files, where each rule defines an effective date window using `from` (inclusive) and optional `until` (exclusive, ending before that date)). When TOML rules exist, `check_ledger` verifies postings within their active window after syntax and balance checks. Verification confirms format compliance and does not substitute for a formal tax opinion.
- `.gitignore`: Standard version control ignore list, protecting backup keys (`.backup_key`), environment secrets (`.env`), and backup archives (`backups/`).

## Document Filing & Journal Preview

When receiving an invoice or bank slip, place the file inside `documents/`. Replace colons `:` with directory separators. Each `EnglishPrefix-中文名称` segment is one folder; keep the hyphen inside the folder name.

```
documents/<account directory path>/YYYY-MM-DD.<note>.<ext>
```

### Filing Example

Bank account `Assets:Bank-银行存款:Main-XX银行对公户` and expense account `Expenses:Operations-主营业务成本:Cloud-云计算与算力`:

- **Bank Receipt**: `documents/Assets/Bank-银行存款/Main-XX银行对公户/2026-02-10.银行回单-云服务扣款.pdf`
- **Vendor Invoice**: `documents/Expenses/Operations-主营业务成本/Cloud-云计算与算力/2026-02-10.XX云算力服务发票.pdf`

When both the date prefix (`YYYY-MM-DD`) and the account directory path match a posting in the transaction (or when the file name contains the transaction's link string, with the `^link` directive's caret prefix stripped), BeanDesk automatically links the file to the transaction. Clicking the document icon in the Journal opens a preview dialog.

## Daily Bookkeeping Walkthrough

Recording a typical transaction involves four simple steps:

### 1. Confirm Account Declarations
Verify the accounts exist in `config/accounts.bean`. Cash and bank accounts require `cash: TRUE`. Contra accounts require a cash flow classification (`cashflow: "..."`):

```beancount
2020-01-01 open Assets:Bank-银行存款:Main-XX银行对公户 CNY
  cash: TRUE
2020-01-01 open Expenses:Operations-主营业务成本:Cloud-云计算与算力 CNY
  cashflow: "purchases"
```

### 2. Archive Evidentiary Document
Place the electronic invoice or receipt into the corresponding account subdirectory under `documents/`.

### 3. Record Transaction Entry
Append the transaction to the current month file (e.g. `data/2026/2026-02.bean`), and ensure the month file is included in `data/2026/2026.bean` (initialized ledgers include the current month by default):

```beancount
2026-02-10 * "XX云网络技术有限公司" "采购年度云服务器及带宽" #cloud #invoice
  Expenses:Operations-主营业务成本:Cloud-云计算与算力      1200.00 CNY
  Assets:Bank-银行存款:Main-XX银行对公户                 -1200.00 CNY
```

### 4. Verify & Inspect Statements
Run a syntax check in your terminal (or via local MCP `check_ledger`):
```bash
bean-check main.bean
```
`check_ledger` runs this syntax check first. If `policies/` contains active TOML rules, it also validates in-window postings against those rules. Once verified with zero errors, switch to BeanDesk. The Trial Balance, Balance Sheet, Income Statement, and Cash Flow Statement update immediately.

## Cash Flow Statement Mapping

If the Cash Flow Statement displays “No cash accounts configured”, check that at least one monetary asset account carries the `cash: TRUE` metadata.

If transactions appear under “Unclassified Items”, assign the appropriate cash flow line to the contra account:

- `cashflow: "<id>"`: Single-direction accounts (e.g., `sales` for revenue, `purchases` for operating costs).
- `cashflow-in: "<id>"` & `cashflow-out: "<id>"`: Dual-direction accounts (e.g., owner advances: `borrowings` for inflows, `debt-principal` for repayments).

Refer to the [Reports](/reports) manual for the complete list of 16 statutory line identifiers.
